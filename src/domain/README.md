# 业务核心与类型边界

`engineCore.mjs` 是网页版本 `engine.mjs` 的独立兼容副本（不读取或更改网页数据）。保留原函数和业务规则，避免原生迁移时更改历史兑换成本、首次阈值和旧档验证语义。

原生 TypeScript 页面统一从 `engine.ts` 导入，`engineCore.d.mts` 提供全部 28 项运行时导出的完整声明，数据结构定义于 `types.ts`；不使用 `any` 或 `ts-nocheck`。将来升级业务规则时，应同时维护核心、声明和 `tests/engine.test.mjs` 的兼容回归。

## 保存与恢复

- 正式存储模型为 `PersistedAppState`：业务版本4、存储版本1、同步索引版本1。SQLite 使用 `sprout-native-sync-v1.db`，浏览器使用 `sprout-native-sync-v1`；不导入或删除旧空间。
- 仓库读取无记录时才初始化；损坏 JSON、未知版本和读取失败均上抛，展示重试页，不覆盖原内容。
- `store.run` 同步锁防连续点击，先复制校验、执行业务，再由 `syncModel.ts` 统一生成所有实体的归属、版本、删除墓碑与不可变事务日志，同一份存档原子保存。事务成功后才发布新状态。无同步元数据或元数据缺损的存档在新空间严格拒绝，不自动重建。
- 初始化即建立稳定本机账户和独立设备编号，头像在上传操作中使用附件引用，主题仅设备本地。`pendingSync`读取整组有序前缀，`acknowledge`验证完整事务并幂等确认；当前不联网、不自动ACK，不提供假远端合并器。详见项目 `DATA_ARCHITECTURE.md`。
- 保存失败保留原状态，返回 `ok: false`；页面应保留输入并允许重试。
- `AppProvider` 在返回前台或每 30 秒刷新本地时间，跨日打卡和奖券有效期基于设备本地时区。

## 回归覆盖

原网页版全部 50 项核心测试迁入，另加存储/仓库测试覆盖初始化、重载、失败回滚、快速重复点击、损坏存档和明确重试。SQLite 单元测试采用事务替身，不代表真实手机端的 SQLite/进程终止测试；设备验证仍需单独执行。
