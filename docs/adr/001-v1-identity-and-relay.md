# V1 身份与离线中继边界

## 已落地

- 小组成员收到的已验证 `groupPeers` 会原样加入下一次发送包，接收方可在不同时刻继续转发。
- 已离组设备仍会缓存并转发收到的日志；本地离组凭据仍只在直连设备确认保存本人日志后清除。
- 中继不重签、不改变原始账号和设备字段；同一批日志按账号去重。
- 离组事件沿用本人账户的成员删除事务，接收方不能替其他账户生成离组事件。

## 身份规则

- V1 是“一安装一身份、一身份一密钥”，不支持复制数据库后继续共用 `accountId`。
- `accountId` 必须由公钥指纹派生；私钥丢失只能创建新身份，不能用新密钥恢复旧 `accountId`。
- 旧版本无签名日志不得因为本机新建密钥而追签，也不得进入中继缓存；重新配对/人工确认后才能进入 V1 信任链。
- 签名邀请必须成为成员公钥进入小组的可信来源；共享口令只负责发现和加密传输，不能单独证明成员身份。

## 原生上线门槛

`src/domain/identity.ts` 提供领域层契约和 WebCrypto/测试实现。Android 原生 provider 已放在
`modules/sprout-identity`，使用 Android Keystore 保存 P-256 私钥；JS 只能调用
`getIdentity/createIdentity/sign/verify/forgetIdentity`，不能读取私钥。它目前还没有替换旧存档的
`accountId`，也没有在真机完成重启/卸载恢复验收，因此不能把整个共享口令会话宣称为“独立成员认证”。
后续 iOS 仍需单独接入 Keychain，当前不属于 Android 交付范围。

## 离线一致性边界

离组吊销只能最终一致：没有收到墓碑的离线设备仍可能暂时显示旧成员。收到墓碑的设备必须缓存
原始签名日志并在下一次遇到任意组成员时转发；没有连接路径的设备不会被凭空更新。
