维护日期：2026-10-23。下表按实际执行机制分类；表示已有断言，不表示本次执行通过。同行券执行结果见[验收记录](./runs/2026-10-23-companion-tickets.md)，原有基线见[基线记录](./runs/2026-10-22-baseline.md)，操作与预期见[功能测试用例](./TEST_CASES.md)。

## 覆盖类型与边界

- **业务/模型**：执行真实业务函数或纯模型，验证输入输出与状态变化。
- **替身集成**：真实状态层/仓库代码配合内存存储、事务或平台 API 替身，不验证真实 SQLite、浏览器存储、相册或网络。
- **源码约束**：读取源码字符串或 TypeScript AST，检查属性、分支与布局声明；不能证明元素渲染、点击、尺寸、焦点或读屏实际正确。
- **抽取执行**：从真实源码抽取表达式/回调，注入替身依赖执行；比字符串约束更能验证逻辑，但没有挂载 React 或完整应用。
- **库/资源验证**：使用实际编解码库、导航路由状态机、安装后的图标目录或资源文件；只证明相应库与资源契约。

当前没有真实浏览器或原生 UI E2E 自动化。所有现有文件由 Node 测试运行器执行；测试标题中出现“实际”“真实”“界面”不改变覆盖层级。源码约束与抽取执行不应记为 UI 用例已通过。

## 按功能变化选择回归

安装包默认流程对应BUILD-001/002。[buildApk.test.ts](../../tests/buildApk.test.ts)以临时文件夹具实际执行 `checkReleasePrerequisites`，覆盖五处版本、两处构建号一致性、当前日志章节以及技能缺失/空值的拒绝行为，只证明结构校验与拒绝行为，不覆盖真实Gradle或复制交付物。真实Gradle、APK元数据/签名核验和交付物保留以当次验收记录为准，不能据此推断设备安装启动、真实局域网或商店发布通过。

同行历史精简对应 COMP-017（UI）：同行与搭配信息直接分行，无折叠按钮。现有 `companionUi` 状态模型和 `ticketLayout` 源码约束仅作为回归，不覆盖伙伴长文本、实际排版或读屏；这部分需项目UI runtime或人工设备验证，不为低影响展示变更增加复述源码的单测。

以下是起点，不是豁免清单；同时影响多个模块时取并集。具体命令、执行状态和独立复核要求见[规范](./README.md)。
