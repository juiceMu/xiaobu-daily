# 功能测试用例库

维护日期：2026-10-23。依据当前工作区源码、`APP_MANUAL.md`、`DATA_ARCHITECTURE.md` 与 `tests/` 建立，包含同行券、小组与局域网功能。手册未描述的小组行为以 `src/domain/groupSync.ts`、`src/state/lanSync*`、相关页面为依据；后续修改必须同时核对手册和源码。

本文件是可执行验收规格，**所有用例初始状态均为 `NOT_RUN`**，不代表已经执行或已经自动化。测试文件存在、源码结构断言、类型检查、静态导出均不能替代真实页面操作或真机验证。执行结果写入运行报告，保留本库稳定 ID；不把发现的缺陷改写成“预期通过”。使用流程和报告规则见 [测试规范](./README.md)。

## 约定与可重复数据

- 优先级：P0 为核心业务、原子保存和账户隔离；P1 为常用流程、边界和异常；P2 为视觉与辅助体验。
- 执行层：`D` 领域/纯函数，`S` 存储/Provider/协议集成，`UI` 页面交互，`DEV` 实际原生设备。`ALL` 表示 Web、Android、iOS；纯函数可在 Node 执行，但不因此宣称三端交互通过。
- 同一行包含多个参数时，每个参数独立执行并记录子结果；任一失败则该行失败。所有变更前后记录实体数量、关键字段和持久化状态，必要时比较 `outbox`、revision、附件与墓碑。
- `F0`：独立测试命名空间/安装中的全新合法存档；真实用户数据不得清空。每例从 F0 或注明的快照恢复，不能依赖上一例残留。通过测试夹具构造复杂状态时，必须经过领域函数及真实 `store.run`/同步初始化校验，禁止凭空拼造非法“正常”存档。
- `T0`：可控本地时间 `2026-10-22 12:00:00 +08:00`；当前周 W0 为 `10-19` 至 `10-25`，上周 W-1 为 `10-12` 至 `10-18`，下周始于 `10-26`。设备手工执行可用真实当天等价日期，报告必须记录时区及映射。时间注入限测试夹具，不直接改生产数据。
- `F1`：F0 上新建任务“测试阅读”，每日目标 3、任选已提供图标与颜色；奖励门槛 2、名称“测试休息券”，到期规则下一周一 `00:00`。不依赖默认任务名称/数量。
- `F2`：F1 在 W0 有 5 次合法打卡，其中 2 次已兑换一张券，未消费次数为 3；另有 W-1 的合法打卡。每次打卡遵守任务每日上限。
- `F3`：通过实际业务生成打卡券、里程碑永久券、从另一身份领取的赠券；每种均准备可用/已用适用状态，并准备已到期未使用券。获得日期、使用日期跨至少两周；另保留未填备注的旧券。
- `F4`：独立目标 A“测试减重”，起点 130、单位“斤”、递减、步长 1；目标 B“测试学习”，起点 0、单位“页”、递增、步长 0.1；两者初始无记录。
- `AB`：隔离设备/存档 A、B，账户和设备 ID 都不同，昵称“测试甲”“测试乙”；跨设备测试再准备 C“测试丙”。保存账户资料后交换实际生成的完整赠券/邀请/回执，禁止把同一账户拷贝当作另一人。
- `FAIL`：仅在可恢复的测试仓库替身或隔离存储中控制下一次读取/保存失败、延迟或损坏内容；执行后恢复环境。原生进程终止、网络和权限故障必须在 DEV 层另测。
- UI 自动化只使用项目提供的 runtime；没有可用 runtime 时记 `BLOCKED` 并说明原因，保留 D/S 可执行结果。人工真机结果与 AI 自动化结果分别记录，不使用外部 computer-use 补位。

## 冒烟顺序

每次功能改动最少执行：`NAV-001 → TASK-001 → CHECK-001 → REWARD-001 → TICKET-002 → STORE-001`。涉及里程碑再加 `GOAL-001/003/004`；赠券加 `GIFT-002/004/008`；小组加 `GROUP-001/003 → LAN-001 → VIEW-002/005`；主题加 `THEME-001/003`。每例仍使用各自可重复前置，不将箭头理解为共享脏数据。涉及跨端依赖必须按适用平台扩大执行，详见测试规范。

## 执行边界与缺口记录

### 安装包默认流程

- **BUILD-001（P1，脚本/本地Node）**：执行只读APK预检，核对package、锁文件根、Expo、Gradle版本及构建号；在临时夹具中制造版本不一致、缺当前CHANGELOG条目或缺项目技能。预期：合法通过，缺失/不一致失败且不启动Gradle，不修改源文件；每次打包在验收记录注明技能/日志内容审查结果。结构检查不等于语义完整性审查。
- **BUILD-002（P1，Android本机构建/DEV另测）**：运行默认构建入口，检查新APK元数据、签名、SHA-256与旧包保留；已有同名交付物时不得覆盖。预期：真实Gradle成功才交付新包，包名与升级构建号正确、沿用既有签名，明确测试包性质；安装启动和业务真机验证单独记录，不因文件生成标记通过。
- **BUILD-003（P0，Android本机构建+DEV）**：执行 `npm run build:apk -- --qa`，核验包名 `com.smallsteps.checkin.qa`、桌面名「小步日常测试」、`sprout-qa` 深链、禁用备份与测试签名；常规包同时保留。安装QA后确认全新独立存档，通过实际UI生成测试记录并重启；再打开常规应用。预期：测试写操作不改变常规应用存档/主题，两个包均能独立启动；QA不自动插入演示数据，交付物带 `-QA` 且不覆盖既有APK。仅生成APK不代表DEV部分通过。

- 本文件未进行交互测试；用例中的“预期”是待验证契约。已有 `tests/` 的断言层级见测试规范/覆盖索引，不把存在测试文件标作 UI 已通过。
- 当前局域网传输仅原生；mDNS依赖共享组播域，VPN、蜂窝、IPv6-only及客户端隔离仍不保证发现。双机系统本地网络权限、TCP监听清理、原生重打包、跨子网设备验证、摄像头与相册均须真实设备证据。
- 邀请码为离线凭证，当前没有在线权威机制全局撤销旧码；共享组口令可以证明成员资格但不能对成员身份作独立签名。不得将这两项描述为已解决的安全保证。
- 当前小组同步及全组视图还需重点执行 LAN-003/004/005、GROUP-009/010、VIEW-005/007；合法分叉/错误群组/跨账户同ID须用可校验的测试夹具，不改坏真实用户存档。未覆盖的场景应记录为新增自动化缺口，不能静默跳过。
- 系统故障注入若无测试接缝，不修改产品代码假造通过；报告 `BLOCKED` 和所需夹具/设备。静态结构测试不能证明Provider挂载、手势、相机释放、视觉与可访问性实际通过。
