## 本地优先数据层（第一阶段）

账户归属、设备编号、实体版本、删除墓碑与待同步事务在统一提交层维护，业务数据和操作日志原子保存；仍完全离线，不搭服务器、不自动上传或确认同步。主题是独立的设备偏好。详细数据结构、接口、限制和后续接云工作见 [DATA_ARCHITECTURE.md](./DATA_ARCHITECTURE.md)。

本次按新的存储结构启用独立空间，不迁移历史记录，也不删除原存档。新空间的数据结构损坏或版本不支持时保留原文并报错，不自动清空。

## 账户资料（本机）

在「更多」点击账户卡进入「账户资料」，设置昵称和头像。昵称与赠券使用同一本地身份，修改资料不会更换身份编号；已有赠券和领取回执保留当时的昵称，新制作或领取的券使用最新昵称。头像可以从相册选择，也可以使用默认头像，处理后的图片保存在本机，不随赠券二维码或回执发送。

只有保存成功后资料才会更新，取消选择照片或保存失败不覆盖原资料。当前没有云端登录、跨设备资料同步或照片上传；清除本机应用数据会删除资料。相册权限和头像选择、重启后的显示仍需真机验证。

## 扫码赠券（离线版）

在「更多 → 赠送与领取」先保存本机称呼，再制作赠券。券名可以自定义，有效期选择「本周有效」或「永久有效」。这是制作一张新的赠券，不转移或消耗自己通过打卡、里程碑获得的奖券。

1. 赠送方制作并确认保存后，展示赠券二维码；以后也能从发出记录重新查看。
2. 接收方在自己的手机打开同一功能，扫码或粘贴完整券码，核对赠送人、券名及有效期，再确认领取。
3. 领取成功后，奖券进入「我的奖券」，可以正常使用并填写备注。本机重复领取会被拒绝。
4. 接收方可展示领取回执码，赠送方扫描后记录领取方；未收到回执时不自动声称对方已领取。

「本周有效」固定在制作手机的本周日结束、下周一00:00到期，二维码保存对应的绝对时间，领取不会重新起算。两台手机应保持日期和时间准确。

本机称呼及编号不是云端认证账号，二维码与回执没有云端防伪或全局核销。不同手机仍可能领取同一份二维码，清除本地数据也会失去本机去重记录。此版本适合相互信任的人使用，不代表联网转账或可靠的单次流转。

相机只在打开扫码界面时请求权限。浏览器相机通常需要HTTPS或本机localhost；用手机访问电脑的HTTP局域网地址时可能无法打开相机，可粘贴券码备用。两台手机各自的localhost不是同一设备地址。原生手机需要运行包含相机依赖的应用；相机拒绝权限时仍可使用券码。

云服务迁移预留：独立本机身份ID、赠券ID、奖券ID、版本化赠券/回执、绝对有效期及收发记录；赠券协议和业务操作独立于界面，并保留传输/服务接口。接云时仍需增加登录、身份绑定、云端领取事务和同步冲突处理；当前不会上传本地数据，也不自动迁移旧离线券的可信状态。

新增二维码矩阵与解码器的中文内容往返测试；这不能代替两台真实手机的摄像头扫码、权限、后台关闭相机与重启持久化实测。

独立的 Expo + TypeScript + React Native Paper 应用，不是 WebView 包装。旧网页 `../sprout-checkin` 保留为参考，两者数据互不影响；本版本不导入或清空网页现有数据。

## 启动

使用 Node.js 24 LTS（本次验证使用24.19.0），不要使用当前终端默认的 Node18。

```sh
cd /Users/lin/work/AI需求/sprout-checkin-native
npm ci
npm start
```

若本机默认 Node 仍是18，可临时使用已有的桌面运行时（不修改系统设置）：

```sh
export PATH=/Users/lin/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin:$PATH
npm start
```

手机和电脑连接同一网络，在兼容 SDK57 的 Expo Go 中扫描开发服务器二维码。官方在本次 SDK58 过渡期建议真机 Expo Go 使用 SDK57，因此采用57.0.30，而非盲目选择最新SDK。后续升级应重新确认兼容性。参考：https://docs.expo.dev/get-started/create-a-project/

`npm run android` / `npm run ios` 需要已有模拟器环境。本次没有安装或启动模拟器。

## 浏览器手机模式测试

需要完整历史效果时，可在开发模式的「更多 → 设置 → 功能效果预览」添加一份最近四周演示记录，或打开 http://localhost:8082/more/growth?demoHistory=1 。演示记录追加至本机实际存档并参与统计，保留原有记录与账户，不重复添加；其他已打开标签页应刷新后再操作。详见 [APP_MANUAL.md](./APP_MANUAL.md#开发预览的演示历史)。正常启动和正式构建不会自动填充。

已补充 React Native Web 支持。在上述 Node24 环境运行 `npm run web`，浏览器打开 http://localhost:8082。Chrome 开发者工具切换设备工具栏（Mac：Command+Shift+M），选择390×844或375宽手机尺寸。只切换网页显示尺寸，不等于真正iOS/Android模拟器。

建议依次验证：

1. 今日新增「测试任务」，每日3次，连续打卡3次，第四次不可打；撤销一次后次数回到2，再补回。
2. 默认每3次兑换1张，兑换后到我的奖券使用，备注「买咖啡」，确认已使用且不可重复使用。
3. 更多→里程碑，新增「减重测试」，起点130、递减、差值1；记录110，累计20张永久券；重录110不增加。换图标后对应奖券同步，删除目标后券仍保留。
4. 今日归档测试任务，在更多→已归档任务恢复，历史次数不丢。
5. 修改奖励规则保存，刷新浏览器，确认记录、备注、规则还在。

浏览器使用独立localStorage键sprout-native-sync-v1；与旧网页和真机SQLite不共享数据，原sprout-native-web-v1保留且不读取。同一浏览器须保持同一地址及端口，隐私模式/清理站点数据会丢失测试存档。不要同时开多个可写测试标签页，以免覆盖彼此存档。周切换/到期边界已有业务单测；浏览器手测不代表原生软键盘、安全区和SQLite已验收。当前仅验证构建和HTTP入口、未执行浏览器UI自动化。

## 已迁移页面

底部仅保留今日打卡、我的奖券、更多。更多中有自定义里程碑、成长记录、已归档任务、奖励设置。

- 今日：任务新增/编辑、每天次数/图标/颜色、打卡/撤销、归档、按周兑换。

- 里程碑：多个目标独立设置起点/递增递减/差值/图标；暂停恢复、删除、历史查看。紧凑目标入口配可搜索列表，不用长卡片网格。
- 成长：上一周/本周切换、每日次数和各任务统计；归档：查看与恢复任务。
- 设置：兑换次数、奖券名、下周指定星期/时间到期，或以后新券永久有效。

首达规则保持原样：130降到110首次跨过20个1斤刻度，发20张永久券；重复达到不再发。删除目标不删除已发券或备注。有记录后规则锁定，但图标仍可修改。

## 设计与手机交互

使用用户指定ui-ux-pro-max制定设计规范，见design-system/sprout-native/MASTER.md。浅色明亮莫兰迪，鼠尾草绿、奶杏、雾蓝和淡紫，系统中文字体、统一向量图标。没有大幅装饰图案。

主要交互目标至少48dp，表单全屏可滚动、键盘避让、可取消；删除/用券二次确认；支持系统减少动画。底栏标签字号上限1.5倍并适配栏高，正文跟随系统缩放。此阶段仅浅色主题。

根据手机预览反馈，排版调整为标题22、卡片标题17、正文15、辅助说明13、按钮14、统计数字26dp；输入仍16dp。卡片减为16dp内边距、18dp圆角；编辑与归档收进任务右上角菜单，保留打卡和撤销主操作。列表移除gap与separator重复叠加，显式限定滚动区域、卡片和按钮收缩行为，避免布局高度被挤压。此调整不清空数据。重叠截图修复仍需在用户当前浏览器尺寸和缩放设置下复验，不能仅凭构建通过声称视觉已验收。

## 数据可靠性

持久化事务成功后才发布状态；保存中拒绝重复提交。失败保留原状态及表单。损坏或未来版本数据不自动重置，显示错误并允许重试。单份JSON存储适合当前小型离线应用；大量长期记录未来应拆分关系表并做性能验证。未实现云同步和备份导入。
